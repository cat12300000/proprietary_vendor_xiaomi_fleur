Proprietary vendor blobs and generated build files for the Xiaomi fleur (MediaTek MT6781), used when building Android 16 based ROMs (tested with AxionOS 2.9, branch lineage-23.2).

This is a fork of z3rh0/proprietary_vendor_xiaomi_fleur with a few build fixes on top. The blob set itself comes from the upstream repo and from the stock firmware dump noted below.

What's in this repo
proprietary/ is the extracted blobs, laid out like the device's partitions (vendor/, system_ext/, and so on).
Android.bp and fleur-vendor.mk are generated by the device tree's setup-makefiles.py and describe how the blobs are built and installed.

The file list is owned by proprietary-files.txt in the device tree (device/xiaomi/fleur). Change it there, not only here.

Changes compared to upstream
Added vendor.mediatek.hardware.bluetooth.audio@2.1 and @2.2 (32-bit, proprietary/vendor/lib/). The audio.primary.mt6781.so blob links against both, and the build's check_elf_file step failed with DT_NEEDED ... is not specified in shared_libs without them. They were taken from the stock vendor image. Both are listed in shared_libs of audio.primary.mt6781, have their own prebuilt library modules, and are in PRODUCT_PACKAGES.
Removed the wlan_assistant.rc copy rule from fleur-vendor.mk. hardware/mediatek/wlan/wlan_assistant already installs the same init file through init_rc, and having both caused a kati error ("overriding commands for target ... wlan_assistant.rc"). The two files were identical apart from a trailing newline.
Removed the stock ImsService module (com.mediatek.ims, versionCode 36). On a LineageOS/AxionOS based framework it crashed in a loop at start with NoClassDefFoundError: com.android.internal.telephony.metrics.TelephonyMetrics, so IMS never registered. The ImsService from vendor/mediatek/ims (versionCode 33, which does not reference that class) is used instead, and the device tree already inherits vendor/mediatek/ims/ims.mk.

Running ./setup-makefiles.py in device/xiaomi/fleur rewrites Android.bp and fleur-vendor.mk from proprietary-files.txt. Two things to know before you do:

The generated output differs from this repo's committed files. In testing, it removed the media.c2@1.2 init and seccomp entries that upstream removed by hand, and it added mediatek-common and mediatek-framework to PRODUCT_PACKAGES. Always check git diff before committing generated output.
The wlan_assistant.rc and ImsService changes above are kept out of regeneration only if proprietary-files.txt marks them with a leading - (extract the file, but don't generate rules for it).
